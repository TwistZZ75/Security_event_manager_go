Выпускная квалификационная работа
Направление: Информационная безопасность

Данный проект представляет собой аналог SIEM-системы Wazuh, разработанный с нуля в рамках дипломного исследования. Система обеспечивает сбор, корреляцию и реагирование на события безопасности в гетерогенной среде (Windows/Linux).
 Основной функционал
 Агенты (сборщики данных)

    Работают как фоновые сервисы ОС.

    Поддерживаются платформы:

        Windows 10 (журналы Security + Sysmon)

        Ubuntu 24 (syslog, authlog, Suricata)

    Выполняют команды с сервера:

        Отключение сети

        Блокировка учётной записи ОС

        Завершение процесса

    Настройка через единый YAML-конфиг (выдаётся вместе с установщиком).

    Легко расширяемая архитектура для добавления новых журналов.

 Сервер (обработка и корреляция)

    Приём событий от агентов через gRPC.

    Обработка по JSON-правилам корреляции (гибкая система фильтрации).

    Поддерживаемые типы агрегации:

        По количеству срабатываний

        По последовательности событий

        По пороговому значению параметра

    Автоматические реакции при срабатывании правила:

        Отправка уведомлений в Telegram и на email

        Исполнение команд на агенте (отключение сети, блокировка, завершение процесса)

    Формирование алертов с привязкой к событию и правилу.

    Управление статусами алертов:

        открыто → взято в работу → выполнено / ложное срабатывание

        Возможность сброса статуса.

 Веб-интерфейс (управление и мониторинг)

    Построен на REST API (gorilla/mux) + фронтенд.

    Возможности:

        Просмотр событий, алертов, правил, пользователей

        Создание/редактирование правил корреляции

        Изменение статусов алертов

        Администрирование пользователей (роли: администратор, аналитик, наблюдатель)

    Ролевая модель (в разработке):

        Администратор — полный доступ + управление пользователями

        Аналитик — основной функционал (без управления пользователями)

        Наблюдатель — (заглушка, планируется ограничение прав)

 Технологический стек
Компонент	Технология
Взаимодействие агент-сервер	gRPC
API для веб-интерфейса	HTTP REST
Роутинг	gorilla/mux
База данных	PostgreSQL + драйвер pgx
Логирование	slog
Контейнеризация	Docker + docker-compose
Язык разработки	Go (сервер), C++ (агенты Windows/Linux)
Запуск системы
Сборка и развёртывание производятся через docker-compose:
bash
docker-compose up -d

Текущие ограничения и планы

    Архитектурные недочёты (например, передача событий в веб-интерфейс по HTTP вместо WebSocket).

    Роль наблюдатель пока не имеет строгих ограничений.

    Код содержит "топорные" инженерные решения (проект разрабатывался одним человеком как пет-проект).

    В будущем планируется:

        Переход на WebSocket для реального времени

        Доработка ролевой модели

        Расширение списка поддерживаемых журналов и ОС
