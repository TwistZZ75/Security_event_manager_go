Этот репозиторий представляет собой выпускную квалификационную работу по направлению обучения "Информационная безопасность". 
Эта работа представляет собой систему обработки событий безопасности, представляющую собой, насколько это возможно, аналог SIEM системы Wazuh.
В ходе разработки использовались следующие технологии:
grpc - для взаимодействия агентов и сервера
http REST API - для взаимодействия сервера с веб интерфейсом
PostgreSQL - драйвер pgx
gorilla/mux - для роутинга
slog - для логирования
docker/docker-compose - для контейнеризации
Система работает следующим образом:
На компьютеры пользователей устанавливаются программы агенты (сервисы ОС) работающие в фоне, их задача собирать логи из журналов, отправлять их на сервер, а также выполнять команды, которые сервер присылает (команды: отключение сети, блокировка аккаунта ос, завершение процесса). Агенты реализованы для windows 10 и для Ubuntu 24 (на других ОС не тестировались, поэтому не могу сказать точно где они будут работать). Реализована поддержка сборов из следующих журналов:
Для windows: журнал безопасности windows и журнал sysmon
Для Linux: syslog, authlog, Suricata
В будущем можно легко добавить поддержку сбора информации из других журналов.
Настройка агентов производится в конфигурационном yaml файле, которых необходимо скачать вместе с установщиком. Настраиваются параметры сервера, а также читаемые журналы.
Задачей сервера является обработка присылаемых агентами событий с использованием правил корреляции. Правила в формате JSON, они отслеживают тип события, устройство и т.п. поддерживают 3 типа агрегации (по количеству срабатываний, по последовательности событий и по пороговому значению какого-то параметра) и 4 вида автоматических реаций на срабатывание (3 из списка команды выше и + отправка уведомления в тг бота и на почту).
Также при срабатывании правила создаётся алёрт в котором указано событие ставшее причиной срабатывания и правило создавшее алёрт. В системе есть возможность отслеживать статус алёрта: "открыто" -> "взято в работу" -> "выполнено" -> "ложное срабатывание", также есть возможность после присвоения статуса его сбросить.
Управление производится через веб-интерфейс. Он позволяет как просматривать информацию о сущностях в системе, так и создавать правила, изменять статус алёртов и работать с пользователями. 
В системе реализованы уровни доступа, пока основных 2 "аналитик" и "администатор", разница между ними в том, что администратор имеет доступ к работе с пользователями. Также пока как заглушка существует уровень доступа "наблюдатель", он присвается пользователю по умолчанию, но функционально пока не отличается от аналитика, в дальнейшем планируется реализовать для этой роли ограничения функционала.
Многие технические и инженерные решения пока находятся в топорном и банально глупом виде, например работу с событиями в веб интерфейсе явно нужно перенести с http на websocket или подобное решение.
Проект разрабатывается 1 человеком и представляет собой скорее большой пет проект, чем что-то серьёзное.  
Запуск системы производится через docker-compose
